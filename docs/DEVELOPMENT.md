# 개발 가이드라인

앱 이름 **같이** · Flutter(웹 우선) + Firebase · 프로젝트 `god-ch` · https://god-ch.web.app
작업 규칙의 원본은 [CLAUDE.md](../CLAUDE.md), 환경 설정은 [README.md](../README.md). 이 문서는 지금까지의 진행 상황을 바탕으로 한 요약이다.

## 1. 구조

- **Feature-first + MVVM**, 추가 상태관리 패키지 없음.
  - 기능 폴더: `data`(저장소) · `view_model` · `view`
  - 공통: `lib/core`(theme, layout, mvvm), 모델: `lib/data/models`
- 화면은 저장소를 직접 부르지 않고 **ViewModel만** 쓴다. ViewModel은 `core/mvvm/view_model.dart`를 상속하고 `run()`으로 busy/error를 관리한다.
- ViewModel은 `ViewModelBuilder`로 만들고 저장소는 `AppScope.read(context)`로 꺼낸다.
- 스트림은 ViewModel 생성자에서 **한 번만** 만든다 (build마다 만들면 재구독으로 깜빡인다).

## 문구 원칙

- **서술형 문장을 최대한 쓰지 않는다.** 제목 · 버튼 · 라벨은 짧은 명사형으로 쓴다 ("디자인 선택", "초대 코드").
- "~를 골라요", "~해 주세요" 같은 안내 문장과 부차적인 설명(부제 · 예시)을 두지 않는다. 오류 · 확인처럼 꼭 필요한 곳만 한 줄로 쓴다.
- 입력칸은 미니멀하게: 채움과 상자 없이 밑줄 하나, 최소 높이 44px (`core/theme.dart`의 `inputDecorationTheme`).

## 2. 데이터와 권한

- 모든 교회 데이터는 `churches/{churchId}/...` 아래.
- 권한은 **`firestore.rules` / `storage.rules`가 강제**한다. 화면에서 숨기는 것만으로는 안 된다.
- **권한 체계**: 앱 개발자(`admin` 계정, 앱 운영자 화면) 위에, 교회 안에서 **교회 관리자 / 교역자 / 회원** 세 단계가 있다.

  | | 교회 관리자 | 교역자 | 회원 |
  |---|---|---|---|
  | 앱 수정 (소속 만들기/이름 · 소속별 기도·성경 켜기 · 노출 · 입장 시 필수 정보 · 기도 설정 · 교회 정보 · 폐쇄 요청 · 차단) | ✅ | ❌ | ❌ |
  | 글 게시 (성경: 말씀 묵상 글) | ✅ | ✅ | ❌ |
  | 조회 · 교역자 업무 (인원 관리 · 입장 요청 승인 · 소속 인원 배치 · 초대 코드(교인용) · 비공개 기도제목 열람/응답 · 삭제 사유 기록) | ✅ | ✅ | ❌ |
  | 교역자/관리자 역할 지정 · 교인 정보 수정 · 추방 · 교역자용 초대 코드 | ✅ | ❌ | ❌ |
  | 기도 · 말씀 이용, 이모티콘 응원, 기도제목 쓰기 | ✅ | ✅ | ✅ (소속 허용 시) |

  - 앱 개발자(`platformAdmin`)는 교회 회원이 아니어도 교회의 모든 것을 고칠 수 있다 (기도제목 내용만 볼 수 없다). 교회 회원이 될 수 없다.
  - 권한은 `firestore.rules` / `storage.rules`가 강제한다 (`isOwner` = 앱 개발자 · 교회 관리자, `isManager` = 거기에 교역자). 서랍의 관리 메뉴도 같은 기준으로 보인다: 교역자는 인원 · 입장 · 소속, 교회 관리자는 거기에 기도 설정 · 교회 정보.
- 비공개 기도제목은 일반 교인 쿼리에 포함되지 않는다. 피드 쿼리에는 `visibility`/`deleted`/`departmentId` 조건을 반드시 넣는다.
- 로그인은 아이디+비밀번호(`loginIds/{id}` → 이메일). 예약 아이디는 `LoginId.aliasEmail`.
- 교회 생성은 `churchRequests` 승인 또는 직접 등록. 입장은 두 길이다 (둘 다 **요청 후 교역자 승인**을 거쳐야 교인이 된다).
  - **공개 탐색**: 교역자가 교회 입장 관리의 **노출**에서 공개를 고르면(`churches/{id}.listed`) 교회 탐색(`/explore`)에 나타나고, 누구나 입장을 요청한다 (초대 코드 없이, 항상 교인 역할 · 승인 대기).
  - **비공개**(기본): 탐색에 나오지 않고 만료 있는 `inviteCodes`로만 들어온다. 공개 교회도 초대 코드를 쓸 수 있다.
- **설정을 바꿀 때는 확인 팝업**(`confirmChange`)을 거친다: 노출 여부, 입장 시 필수 정보, 소속별 기도 · 성경, 기도 요청 운영 설정 저장. 새 설정 화면을 만들 때도 같은 방식으로 실수나 가벼운 선택을 막는다.
  - 초대 코드는 역할 · 소속(선택 박스, 0~1개) · **일회용** 여부를 정한다. 일회용 코드는 그 코드로 입장을 신청하는 순간 신청과 같은 트랜잭션에서 사라진다.
  - 입장 시 필수 정보(주소 · 생년월일)는 코드가 아니라 입장 관리의 **"입장 시 필수 정보"** 카드에서 교회 전체에 한 번 정한다 (`churches/{id}/settings/join`). 전화번호 인증은 SMS 인증을 만들기 전까지 쓸 수 없다.
- 입장 요청(승인 대기) 수는 왼쪽 메뉴 "인원 관리"의 숫자 배지와 알림 버튼의 **N** 표시에 반영된다. 읽지 않은 알림이 있어도 N으로 표시한다.
- 콘텐츠 종류는 말씀묵상(`devotions`) 하나이고 `ContentKind`와 `firestore.rules`가 **일치**해야 한다.
- 이미지는 교회 · 회원 썸네일(Storage, 256px 정사각 JPEG)뿐이다.
- **새 필드를 추가하면 모델 · 저장소 · `firestore.rules`의 `hasOnly([...])`를 같이 고친다.** 새 쿼리가 복합 조건이면 `firestore.indexes.json`도 고친다.

## 3. 정보 구조

**기능은 기도제목 · 모임 · 성경 셋뿐이다.** 레이아웃을 고르는 방식(페이지 편집 · 디자인 갤러리 · 스타일/팔레트)과 공지 · 일정 · 사진첩 · 설교영상은 없앴다. 새 기능은 하단 탭이나 서랍에 항목만 더하고, 화면마다 모양은 하나다.

### 하단 탭과 서랍 (모바일)

| 하단 탭 | 화면 | 내용 |
|---|---|---|
| 일정 | 모임 | 교회 모임 카드 (모임장 · 정원 · 참여) |
| 기도 | 기도제목 | 공개 기도제목이 포스트잇 카드로 떠다닌다. 교회의 첫 화면 |
| 말씀 | 성경 | 말씀 묵상 글과 내 묵상 |
| 내 활동 | 내 활동 | 내 기도제목 · 내 묵상 (앱 개발자에게는 없다) |

- 하단 바는 알약 모양이고 네 칸이 같은 크기다 (`_PillTabBar`). 홈은 없다.
- **서랍**: 앱 이름 아래에 조금 띄워 **내가 속한 교회**(교회 바꾸기), **교회 탐색**(공개 교회를 찾아 입장 요청). 교역자에게는 관리 메뉴(인원 → 입장 → 소속, 교회 관리자는 기도 설정 · 교회 정보)가 더해진다.
- **서랍은 교회 안에만 있다.** "내가 속한 교회"(교회 목록)와 "교회 탐색"은 교회 위에 쌓이는 **별도의 화면**이라 서랍이 없다. 다만 **오른쪽 계정 띠(`AccountRail`)는 교회에 속하지 않았어도 볼 수 있어서** 이 화면들에도 늘 붙어 있다.
- **프로필과 설정은 MECE로 나눈다.** 프로필(오른쪽 띠의 프로필 사진)은 *나에 관한 것*: 내 정보와 비밀번호 — `showAccountDialog`. 설정(톱니바퀴)은 *앱 자체에 관한 것*: 화면 모드 · 앱 정보 — `showSettingsDialog`.
- 오른쪽 계정 띠(프로필 · 알림 · 로그아웃 · 설정)는 56px 폭이고, ☰를 누르면 서랍과 함께 열려 두 너비의 합이 화면 너비가 된다.
- **소속**(부서의 역할): 교회 운영자가 소속을 만들고(`churches/{id}/affiliations`), **교역자 · 교회 운영자가 교인을 소속에 넣는다.** 교인은 여러 소속에 **중복해서** 속할 수 있고(`members.affiliationIds`), **스스로 고를 수 없다** (규칙에도 본인 수정 경로가 없다). 소속은 회원 상세 관리의 체크박스나 소속 관리의 인원 배치, 초대 코드(역할 · 소속 · 일회용)로 정한다. 교회 운영자는 모든 소속에 자동으로 속한다.
  - **소속별 허용**: 교역자가 소속마다 기도 · 성경을 켜고 끈다 (`settings/features`, `ChurchFeatures`). 설정한 적 없으면 모두 허용이고, 속한 소속이 모두 꺼져 있으면 "본 서비스가 허용되지 않았습니다"만 본다 (`FeatureGate`). 속한 소속이 없는 교인과 교역자는 막히지 않는다.
  - **소속 전용 기도제목**: 기도제목은 교회 전체 또는 내가 속한 소속에 올린다 (`affiliationId`). 기도 화면 위쪽 탭의 소속 선택(`AffiliationSelect`)으로 볼 소속을 고른다 ("전체"는 없다). `firestore.rules`의 `inAff` · `featureAllowed`가 같은 기준으로 막는다.
  - 내 정보의 "내가 속한 교회"에서 내 소속을 보기만 한다 (`MyAffiliationsCard`).

### 목록과 상세 (기도제목 · 모임 · 성경)

- **목록 모양은 사용자가 고른다**: 알록달록(색이 있는 카드) / 심플(글 중심 목록). 위쪽 탭 오른쪽의 스위치(`ListStyleToggle`)로 바꾸고, 기기에 저장된다 (`ListStyleController`). 세 화면이 함께 따른다. 알록달록 기도제목은 포스트잇이 떠다니는 화면(배경은 바깥 틀이 깐다), 심플은 목록이다.
- **줄 가장자리에 조회수와 좋아요**가 세로로 보인다 (`StatIcons`). 줄을 누르면 **분리된 카드**로 상세가 열린다.
  - 성경 `/churches/:cid/devotion/:id`: 말씀 · 묵상 · 반응(좋아요, 조회수) · 댓글(교인의 묵상, 한 사람 한 개). 말씀 글에는 `meditation`(교역자의 묵상), `views`, `likedBy`가 있다.
  - 모임 `/churches/:cid/meeting/:id`: 정보 · 소개 · 참여(정원 막대, 신청 · 취소) · 반응. 교인이 만들면 모임장이 되고, 참여자는 `participantIds`에 담기며 정원은 규칙이 막는다. 모임장 · 교역자는 고치고 지운다.
  - 기도제목: 기존 상세(본문 + 이모티콘 응원 + 교역자 댓글)에 `views`가 더해졌다. 목록의 "좋아요"는 이모티콘 응원의 합이다.
- 조회수는 상세를 열 때 +1, 좋아요 · 참여는 내 uid를 `likedBy` · `participantIds`에 더하고 빼는 것만 규칙이 허용한다 (`onlyMeDiff`, `viewBump`).
- 교회 정보 관리의 **샘플 데이터** 버튼은 기도제목 8 · 말씀 8 · 모임 7개를 넣는다 (`SampleDataRepository`, 교역자는 견본에 한해 조회수 · 좋아요 · 참여자를 채워 만들 수 있다).

### 기도 설정

- 교회 관리자는 서랍의 **기도 설정**에서 운영 방식을 정한다 (`PrayerSettingsPage`, `PrayerSettingsPanel`). 라디오 · 체크 · 선택 박스이고 `churches/{id}/settings/prayer`에 저장된다 (`PrayerSettings`). 정한 적 없으면 표준 설정이다.
- 작성: 쓸 수 있는 사람(교인 전체 / 교역자만).
- 공개 범위: 교역자 전용 비공개 허용 여부, 기본 공개 범위. 비공개 글은 일반 교인 쿼리에 포함되지 않는다.
- 이모티콘 응원: 쓸 수 있는 이모티콘(🙏 ❤️ 💪 🕊️)을 고르고, 이모티콘별 개수 표시 여부를 정한다. 모두 끄면 응원이 사라진다. 반응한 사람의 이름은 노출하지 않는다.
- 삭제: 교인 본인 글 삭제 허용, 교역자 삭제 시 사유 필수. 삭제는 소프트 삭제이고 교역자가 복구할 수 있다.
- 교역자: 공개 글 교역자 댓글, 비공개 글 교역자 응답, 비공개 글 열람 기록(접근 기록). 일반 교인의 댓글 · 자유 답글은 없다.
- 규칙(`firestore.rules`의 `prayerOpt`)이 작성자 · 비공개 · 응원 종류 · 삭제 · 댓글 · 응답을 같은 기준으로 막는다.
- 아직 없는 것: 기도 응답 나눔, 교역자 답변 푸시 알림, 삭제 글 자동 영구 삭제 기간.

## 4. UI 규칙

- 공통 위젯: `PageFrame`, `CardGrid`, `SubPage`, `showAppDialog`, `ManageListRow`(76px 고정 행), `BlurValidatedField`(포커스 이탈 시 검증), `RequiredLabel`(빨간 *).
- 색·모서리·깊이는 `core/theme.dart`만 쓴다. 하드코딩하지 않는다.
  - `AppColors`(light/dark 팔레트), `AppRadius`(control 4 · card 6 · panel/dialog 8), `AppDepth`(raised · brand 네온 그라데이션 · glow)
  - 모서리는 아주 약하게. 알약/큰 둥근 모서리 금지 — 예외는 원형 아바타 · 선택 점과 **하단 알약 탭 바**.
  - 포인트 면은 `AppDepth.brand`(파랑→보라→마젠타). 채움 버튼은 테마가 자동 적용.
- 레이아웃: **모바일 전용**으로 설계한다 (요구사항: [REQUIREMENTS_LOGIN.md](REQUIREMENTS_LOGIN.md)). 새 화면은 모바일 기준으로 만들고, 넓은 화면(`kNarrow` 800 이상, `kContentWidth` 880)은 차후 관리자용 데스크탑 개발 때까지 새로 손대지 않는다. 기존 데스크탑 코드는 지우지 않고 유지한다.
- 라이트·다크 둘 다 확인한다. 글자색은 배경 위에서 읽혀야 한다.
- 이미지는 `Image.network(..., webHtmlElementStrategy: WebHtmlElementStrategy.fallback)`(또는 `ThumbnailAvatar`)로 불러 CORS를 피한다.

## 5. 작업 순서

1. 모델 → 저장소 → 규칙/인덱스 → ViewModel → View 순으로 만든다.
2. `dart format lib` → `flutter analyze`(경고 0) → `flutter build web --no-wasm-dry-run`.
3. 규칙을 바꿨으면 `firebase deploy --only firestore:rules --dry-run`으로 문법 검사 후 배포.
4. 커밋은 요청이 있을 때만. 메시지는 한국어, 변경 요지를 한 줄로.

## 6. 배포

```
firebase deploy --only firestore            # 규칙 + 인덱스
firebase deploy --only storage              # 이미지 저장소 규칙
firebase deploy --only hosting              # 빌드(build/web) 후
```

- Storage 버킷 CORS는 `tool/cors.json`을 `gsutil cors set`으로 한 번 적용해야 한다.
- 말씀묵상 성경 본문은 Storage `bible/verse.csv`(저장소에는 커밋하지 않음, `/data/bible/*.csv`는 gitignore).
- 앱 운영자 계정은 `tool/create_admin.ps1`로 만든다. **비밀번호는 저장소에 커밋하지 않는다.**

## 7. 환경 주의사항 (Windows)

- PowerShell 5.1의 `Set-Content -Encoding utf8`은 BOM을 붙인다. **`firestore.rules`는 BOM 없이** 저장한다.
- PowerShell 문자열로 치환할 때 `$(database)` 같은 `$`가 변수로 풀리지 않게 작은따옴표 here-string을 쓴다.
- 웹 핫 리로드는 불안정하다. 이상하면 완전히 다시 실행한다. 개발 실행은 `.vscode/launch.json`의 "웹 (로그인 유지)"(포트 5000).

## 8. 미결 사항

- 전화번호 인증(SMS)은 미구현이다 (Blaze 요금제와 전화번호 연결 단계가 필요). 입장 시 필수 정보에서는 비활성 칩으로만 있다.
- 개인정보 제3자 제공 동의 문구(`features/auth/view/consent_checkbox.dart`)는 초안이다.
- 데스크탑은 일반 사용자에게 제공하지 않고 차후 별도 관리자용으로 개발한다. 웹 폐쇄 방식(사이트 내리기 / 안내 화면)은 정해지지 않았다.
- 교회 전체 색 프리셋(테마)은 차후 과제다.
- 변경은 대부분 아직 **커밋 · hosting 배포 전**이다 (firestore 규칙은 한 차례 배포됨, 이후 `group`/기도제목 규칙 변경은 재배포 필요).
