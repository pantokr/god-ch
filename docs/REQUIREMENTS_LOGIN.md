# 요구사항: 로그인 · 회원가입

상태: 초안 (확정 전 항목은 "미결"로 표시)

## 1. 로그인 방식

| ID | 요구사항 | 비고 |
|----|----------|------|
| L-1 | 구글 로그인을 지원한다. | 현재 구현됨 |
| L-2 | 일반 로그인은 아이디(ID) + 비밀번호(PW)이다. | 현재 구현됨 (`loginIds/{id}` → 이메일) |
| L-3 | 네이버·카카오 같은 다른 소셜 로그인을 나중에 붙일 수 있어야 한다. | 로그인 제공자를 한 곳(인증 저장소)에서 추가할 수 있게 설계. 지금 구현하지 않음 |

## 2. 보안 · 접속 환경

**모바일 앱 전용**으로 서비스한다. **웹 접속은 폐쇄**한다 (모바일 브라우저 포함). 데스크탑은 일반 사용자에게 제공하지 않고, 차후에 **별도의 관리자에게만** 제공하도록 따로 개발한다.

| ID | 요구사항 | 비고 |
|----|----------|------|
| S-1 | 모바일은 간편하게 로그인한다 (추가 인증 없음). | 로그인 유지 |
| S-2 | 일반 사용자의 웹(데스크탑·모바일 브라우저) 접속은 제공하지 않는다. | 현재 호스팅(god-ch.web.app)의 처리는 3절 |
| S-3 | 데스크탑 관리자 기능은 차후 별도 개발한다. 이때 추가 보안(2단계 인증 등)을 함께 설계한다. | 이번 범위 아님 |
| S-4 | 권한은 계속 `firestore.rules`가 강제한다. | 화면에서 막는 것만으로는 부족 |

## 3. 미결 사항

- 데스크탑에서 열면 "모바일에서 접속해 주세요" 안내만 보여줄지, 아예 막을지.
- 현재 배포된 웹(https://god-ch.web.app)을 내릴지, 안내 화면으로 바꿀지. 내리면 앱 설치 경로(스토어 배포 또는 직접 배포)가 먼저 필요하다.
- 차후 데스크탑 관리자의 범위: 앱 운영자만인지, 교회 운영자도 포함하는지. 계정 구분(별도 관리자 계정인지 기존 역할인지).
- 기존 데스크탑 레이아웃(사이드바 등 넓은 화면 코드)은 관리자용으로 재활용할 수 있으니, 당장 지우지 않고 유지한다.

## 4. 회원가입

| ID | 요구사항 | 비고 |
|----|----------|------|
| R-1 | 구글로 가입하면 추가 입력 없이 **바로 가입**된다. | 구글 계정의 이름·이메일 사용 |
| R-2 | 아이디/비밀번호로 가입할 때는 아이디·비밀번호에 더해 **이름**을 받는다. | 필수 입력 |
| R-3 | 가입 후 교회 입장은 기존대로 만료 있는 초대 코드로만 한다. | |
| R-4 | 비밀번호 규칙과 아이디 중복 검사는 입력칸에서 포커스를 벗어날 때 알려준다. | 현재 구현됨 |

## 5. 추가 정보 (확장)

나중에 요구할 수 있는 정보: 주소, 생년월일, 이메일, 사용자 인증(본인 확인).

- A-1 추가 정보는 필수 여부를 바꿀 수 있어야 한다. 현재는 교회가 초대 코드의 `requiredFields`로 지정한다.
- A-2 이미 가입한 사용자에게도 새로 필수가 된 정보를 나중에 입력받을 수 있어야 한다 (로그인 직후 보충 입력 화면). 미결: 입력 전까지 앱 사용을 막을지.
- A-3 새 항목을 추가할 때는 모델 · 저장소 · `firestore.rules`의 `hasOnly([...])`를 같이 고친다.
- A-4 개인정보 수집 항목이 늘면 동의 문구(`consent_checkbox.dart`, 현재 초안)를 갱신한다.
- A-5 사용자 인증(본인 확인) 방식은 미결 (휴대폰 인증 등).

## 6. 현재 구현과의 차이 (점검 필요)

- 이메일 인증은 제거된 상태다. 추가 정보의 "이메일"을 인증된 값으로 쓸지는 미결.
- 웹 추가 보안(S-2)은 아직 없다.
- 구글 가입의 이름·전화번호 처리, 기존 사용자 보충 입력(A-2)은 확인 후 정리한다.
